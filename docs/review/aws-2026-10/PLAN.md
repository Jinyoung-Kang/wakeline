대상은 AWS 서울 리전에 올린 Wakeline 공개 데모입니다(ADR-039, EC2 `i-01a2eeec216bd9ce2`, RDS `portfolio-pg`, CloudFront `d2adhtsiw2qcr6`).
코드 기준은 `main` `48c18826`이며, EC2에 배포된 코드와 같습니다. 이 문서는 **승인 전 계획**이고, 승인 전에는 코드를 고치지 않았습니다.

## 0. 요약

- 이미 큰 리뷰를 여러 번 거친 코드입니다(리뷰 v1, CTO 리뷰, QA 2회, 적대적 리뷰 2회). 기준선 시험도 모두 통과합니다. 구조 규칙(api 계층 · 수집기 층 · 웹 데이터 접근)은 가드 시험이 이미 지키고 있습니다.
  **새 계층 · 추상화를 더할 근거는 찾지 못했습니다.**
- 위험은 **AWS 운영 방식**과 기존 코드의 전제가 어긋나는 데 몰려 있습니다. 운영 방식은 평일 09–18시만 켜고(주말 약 63 h 꺼짐), 다른 두 프로젝트와 함께 쓰는 1 GB RDS · 앞단 잠금이 있으며, 로컬과 같은 외부 API 키를 씁니다.
  - 매주 반드시 생기는 데이터 손실 2건이 있습니다.
  - 지금 AWS에서 기능 하나가 멈춰 있습니다.

- 보안 결함 중 Critical · High는 없습니다. 인젝션 · 인증 우회 · 비밀값 노출도 찾지 못했습니다. 실행 환경의 프레임워크 · 런타임은 모두 지원 기간 안입니다.

### 2.3 고치지 않을 것(이유)

- **B-3** 특보 `ended_at`이 밤 · 주말 정지 뒤 첫 수신 시각으로 저장되는 문제: 이 값을 읽는 화면이 없습니다(`/warnings/history`는 공개 API에만 있음). 정직하게 고치려면 '해제 시각 모름' 필드와 계약 개정이 필요합니다. → 남은 위험으로 기록합니다.
- **B-7 · RDS 메모리**: 일 집계 `work_mem 64MB`와 공유 풀 6 연결이 1 GB RDS 스왑에 기여한다는 것은 **추정**입니다. DB 계정 없이는 `EXPLAIN ANALYZE`로 잴 수 없고, 측정 없이는 바꾸지 않습니다. → 측정 방법과 함께 남은 위험으로 둡니다.
- **B-5**(기동 때 오래된 상태 최대 10 s), **B-8**(공역 읽기 전 5분 캐시 — 계약 결정 필요), **B-9**(보존 항적 경계 — 계약 개정 필요), **C-3**(금요일 마지막 10분 예산 통계), **C-4**(기동 때 Redis 한 번 읽기 — 실측에서는 정상), **A-2**(503 경고 지문 — 고치면 운영자 '해결' 표시가 풀림): 영향이 작거나 계약 · 운영 결정이 먼저 필요합니다.
- **공유 호스트 설정**(Redis `vm.overcommit_memory=0` 경고, Docker 빌드 캐시 5.6 GB): aws-deploy · 다른 프로젝트와 함께 쓰는 설정이라 이번 범위 밖입니다. 보고만 합니다.
- **ESLint 10 올리기**: 개발 전용이고 CTO 리뷰에서 보류했습니다. 지금 `eslint-config-next`가 지원하는지 확인만 하고, 지원하지 않으면 보류를 유지합니다.

## 4. 검증과 배포

1. **커밋마다**: 해당 앱의 시험 · 린트 · 타입 검사. web은 `eslint` · `tsc` · `npm run build` · `check:first-js`(예산 550,000 B)까지 봅니다.
2. **끝나기 전**: 아래를 모두 돌립니다. 이미지를 다시 빌드하므로 로컬 운영 스택 이미지는 `:mainsafe`로 보존해 두었고, 끝나면 `:local`로 되돌립니다.
   - `make test` · `make contract` · `make e2e`(격리 8701) · `make security`
   - `cd apps/api && ./gradlew test`를 캐시 없이 한 번
   - 그 뒤 처음 보는 리뷰어 입장의 별도 에이전트에게 전체 변경을 검토받고, 정확성 · 요구사항에 영향을 주는 것만 고칩니다.
3. **문서**
   - ADR-039에 덧붙임을 씁니다. 운영 일정 가정(따라잡기 · ETag), IPv6, RDS TLS 검증, 외부 키 분리를 담습니다.
   - VERIFICATION `#137~`에 기록합니다.
   - `docs/review/aws-2026-10/REPORT.md`에 변경 · 이유 · 검증 증거 · 남은 위험을 정리합니다.
4. **배포**(승인 범위 안에서): `main` 병합 커밋 → GitHub push → EC2 `/opt/portfolio/wakeline`에서 `git pull` → wakeline compose만 다시 빌드 · 기동(`--wait`) → 상태 · 로그 · 공개 API · CloudWatch 확인.
   EC2 빌드 동안(추정 10–20분) 같은 서버의 Macro · BuildRisk가 느려질 수 있습니다. 실패하면 이전 커밋으로 되돌려 다시 기동합니다.
