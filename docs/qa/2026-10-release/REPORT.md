## 4. 검증하지 못한 부분과 까닭
- 실제 공급자 응답의 특보 해제 줄 · 긴 해제예고 · 행 상한 초과, 실제 공역 파일(이용 조건상 저장소 밖) — 받은 표본에 없다. 키 일부가 오류 글에 남는 경로는 코드 읽기만(미확인).
- `/` 모바일 Lighthouse TBT 가운데 3.0 s(1.1–6.2 s) — PERF §15 개선 뒤 값(871 ms)보다 크지만 같은 조건의 main 이미지 기준을 재지 않아 회귀로 판단하지 않았다(소프트웨어 GL ·
  실행 사이 5배 흔들림). 실제 GPU · 기기에서 다시 잴 것.
- 실제 화면 낭독기 출력 · Safari/Firefox · Android 브라우저 알림 · 실제 터치 기기, amd64/CI 수치.
- 숨은 탭 조회(QA-706)와 다른 탭 동기(QA-712)는 단위 시험(mini-dom)으로 — 실제 브라우저의 백그라운드 탭 · 알림 허락 바꿈은 손으로 보지 않았다.
- DB 멈춤 때 `/alerts/{id}` · `/warnings/history` 의 3 s 한도 · 503 은 코드 경로(`Sql.publicRead` → 앞선 QA-104 의 공통 처리)로 확인 — 이번에 실제로 멈춰 보지 않았다.
- WS 이진 프레임의 호스트 쪽 1006(도커 망 안에서는 1003) — Docker Desktop 포트 전달 현상으로 판단.

## 6. 출시 가능 여부 — **출시 가능(조건 2가지)**
- 근거: 치명 · 높음 결함 0. 찾은 22건(보통 5 · 낮음 17)은 모두 근본 원인을 고쳤고 같은 재현 시험이 통과한다(독립 검토 확인). 회귀 전체 · E2E · 보안 게이트 · 성능 목표 · 첫 화면 JS 예산을 지킨다.
  알려진 취약점 0, 런타임 · 프레임워크는 모두 지원 기간 안.
- 조건 1: §G53 과 '고치며 정한 것' 4가지(특히 QA-709 의 특보 수 표시 · QA-600 의 DB 장애 응답)를 사용자가 받아들일 것 — 받아들이지 않는 것은 그 커밋만 되돌리고 결함은 '남음'으로.
- 조건 2: 병합 뒤 배포(`make up`)하고 운영에서 'wx' 탭 · 관심 탭 · `/m` 을 한 번 열어 볼 것(이번 QA 는 fixture 자료).
- 참고(결함 아님): Node.js 24 활성 지원이 2026-10-20 에 끝난다(보안 지원 2028-04-30 — 26 LTS 는 10-28), Python 3.13 은 보안 수정만 받는 단계 · 패치 하나 뒤(3.13.16), Next 16.4 가 나왔다.

## 7. 수정 우선순위 제안(남은 것 — 모두 개선 제안 · 미확인)
1. 버린 특보 줄의 특보를 이력에서 끝내지 않기(DEFECTS 개선 9) — QA-602 수정으로 너무 긴 줄이 '목록에서 빠짐 → 끝'이 됐다. 실제로 나면 이력이 끊긴다.
2. 특보 오류 글 · 원문에 키 일부가 남는 경로 전수 확인(미확인 1).
3. `/` 모바일 TBT 를 실제 기기 · main 기준과 같은 조건으로 다시 재기(§4).
4. 입력 공백 처리 공통화(`strip()` 이 탭 · 0x1F 도 지움 — 개선 1), 관심 탭의 DB 장애 표시(개선 10), `seenAlerts` 정리(개선 5).
5. 런타임 판 올리기 계획: Node 26 LTS(10-28 뒤) · Python 3.13.16 · Next 16.4 — 각 판의 공지를 확인한 뒤.
