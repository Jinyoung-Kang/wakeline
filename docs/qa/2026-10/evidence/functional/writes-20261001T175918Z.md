## 덧붙임(같은 날 18:0x UTC — 위 표의 '어긋남' 정리)
- `settings 응답 version …` · `resolutions 응답 upto …` 의 '어긋남'은 점검 스크립트의 판정 실수(기대값을 True 로 넘김)다 — 고친 뒤 직접 확인: metar_poll_s 는 값 600 그대로 version 1 → 2,
  해결 표시는 201 → 목록에 보임 → 204 → 다시 404(위 표). 스크립트는 고쳤다.
- `client-errors body_8193(·_chunked)` 의 400 은 사례가 틀렸다(본문 8,175 바이트 — stack 8,100자 규칙에 먼저 걸림). 8,433 바이트(필드는 모두 상한 안)로 다시: Content-Length · chunked 모두
  **413 TOO_LARGE**(`body must be at most 8192 bytes`). 스크립트의 사례도 고쳤다.
- `stats.aggregate day=-999999999-01-01` → 500 은 QA-202(운영 경로), `day=-5000-01-01` → 200 은 QA-208(day = '-infinity' 행 — 정리함, qa-208-aggregate-bc-day.txt).
