## 4. 검증하지 못한 부분과 이유
- **실제 AWS 위의 동작**: CloudFront 캐시 · 오류 페이지 · WS, 보안 그룹, 실제 RDS 의 확장 · `spatial_ref_sys` 소유자와 RDS 전용 객체, EC2 정지 순서 · 실제 하드웨어 성능 — 운영 환경이라 읽기만 했다. 고친 백업 · 복원도 실제 RDS 에서는 돌리지 않았다(리허설 흉내).
- **운영자 터널의 Secure 쿠키**: QA-1600 뒤 운영 쿠키가 Secure 다. Chrome · Firefox 는 `http://localhost` 의 Secure 쿠키를 받는 것으로 알고 있으나 Safari 는 확인하지 못했다 — 배포 뒤 터널 로그인을 한 번 확인해야 한다(안 되면 `.env` 에 `AWS_COOKIE_SECURE=false`).
- **Macro 복원**: 새 `backup.sh` · README 절차를 Macro DB 는 빈 자료로만 리허설했다.
- **실제 공급자 장애 · 실기기 · 화면 낭독기 · Safari**: 외부 호출 금지 · 도구 없음.
- **gate 동시성(QA-1602)의 독립 재현**: 검증 에이전트 하나가 모델 안전장치로 중단됐다 — 수정 뒤 gate 단위 시험(메모리 실측 포함)으로만 확인했다.
- **CloudFront → Caddy 평문 구간**: 로컬로 재현할 수 없어 설계 위험으로만 적었다.
