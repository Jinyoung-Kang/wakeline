# ADR-012 기상청 레이더 합성자료(FR-31)의 지도 정합

**상태** 채택 · 2026-09-27

## 배경
RainViewer 는 전세계 커버리지지만 줌 ≤ 7, 10분 간격이다. 기상청 API허브 레이더 합성자료(HSR)는 500 m · 5분이지만 Lambert conformal conic 격자의 바이너리로 제공된다. 지도(웹 메르카토르)에 겹치려면 좌표 정의가 필요하고, 그 정의는 추정하지 않고 문서에서 가져와야 한다(정직성 규칙).

## 근거(확인한 출처)
- API허브 첨부 "레이더 합성자료 포맷 정보"(PDF): 헤더 1024 B = RDR_CMP_HEAD 64 B + RDR_CMP_STN_LIST 20 B × 48, 반사도 short×2305×2881, 값 = dBZ×100, −20000 표시 최소, −25000 관측영역 내 비관측, −30000 관측반경 밖, 지도 HB: LCC, 기준 N38.0 E126.0, 기준 격자점 (1121, 1681), 500 m, 기준점은 왼쪽에서 560 km · 아래에서 840 km.
- 기상기후데이터위키 "레이더:기상레이더" 6.3: `+proj=lcc +lat_1=30 +lat_2=60 +lat_0=38 +lon_0=126 +x_0=0 +y_0=0 +ellps=WGS84 +units=m +no_defs`, `Affine.scale(500,500) * Affine.translation(-1121,-1681)`, `np.frombuffer(..., int16, offset=1024).reshape(ny, nx)` (행 0 이 남쪽).
- 실응답 헤더(fixtures/kma_rdr_cmp_head.bin): version 1, ptype 5(HSR), map_code 1, nx 2305, ny 2881, dxy 500, 레이더 17곳 — 문서와 일치.

## 결정
1. collector 가 5분마다 파일 목록에서 새 tm 을 골라 바이너리(gzip, 0.8 MB)를 받고, 헤더를 검증한 뒤 반사도 격자를 **서버에서 웹 메르카토르로 최근접 재투영**해 RGBA PNG(1152×1324, ≈65 KB)로 만든다. LCC 이미지를 네 모서리로 억지로 늘리는 방식은 쓰지 않는다(왜곡).
2. PNG 와 그 메르카토르 축 정렬 경계(lon/lat 네 모서리)를 Redis 에 두고(최근 12프레임, TTL 3 h), api 가 `/api/v1/radar/kr` 로 프레임 목록·좌표·투영 정의·범례를, `/radar/kr/{tm}.png` 로 영상을 준다. 브라우저는 MapLibre image source 로 겹친다.
3. 격자점 중심/모서리 관습 차이(≤ 250 m)는 500 m 해상도 아래이므로 문서 정의를 그대로 쓰고 화면에 명시한다.
4. 색 구간(5 dBZ 부터 12단계)은 표시용 선택이며 범례에 "표시용" 으로 적는다. 관측 반경 안은 연한 회색(마스크), 밖은 투명.

## 검증
- 단위 테스트: 실헤더 파싱, 합성 격자에서 기준점(N38 E126) 바로 북동쪽 에코가 재투영 PNG 의 해당 픽셀에 오는지.
- 브라우저: 같은 시각(19:50 KST = 10:50Z)의 RainViewer 프레임과 겹쳐 서해안 북부 에코대·전남 해안·부산 남동 해상 에코의 위치가 일치함을 확인(독립 소스 대조).

## 비용
5분마다 목록 1회 + 바이너리 1회(첫 기동 백필 최대 4회) ≈ 576~600 회/일, 자체 예산 1,000. 재투영 0.7 s(M1). Redis 프레임 12 × ≈90 KB(base64).
