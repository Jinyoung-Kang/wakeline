# ADR-013 수요 기반 정밀 추적: 뷰포트 핫 리전 + 선택 항공기 집중 추적

**상태** 채택 · 2026-09-28

## 배경
전세계 스냅샷(OpenSky)은 크레딧 한도 때문에 120초 간격이라 항적이 꺾인 선으로 보인다. 무료 공급자의 호출량은 한정돼 있으므로, 사람이 실제로 보고 있는 곳에만 호출을 더 쓴다.

## 확인한 사실(2026-09-28 실측·문서)
- adsb.fi opendata: `/v2/icao/{hex[,hex...]}` 로 여러 hex 를 한 요청에 조회(5대 0.39 s 실측), `/v3/lat/{lat}/lon/{lon}/dist/{nm}` (≤ 250 NM). 공개 엔드포인트는 "1 request per second", 개인·비상업, 출처 표기(README 인용).
- adsb.lol: 같은 IP 에서 관심 지역 10 s 수집 중 `/v2/hex` 조회가 429 — 정밀 추적을 얹을 여유가 없다.

## 결정
1. **수요는 서버가 세션에서 만든다.** 브라우저는 임의 지역·주기를 요청하지 못한다. api 가 각 WS 세션의 뷰포트·선택을 보고 수요를 계산해 Redis 임대(lease)로 기록한다.
   - 선택 항공기가 있으면 그 세션은 **집중 추적(focus)** 수요만 낸다(핫 리전 수요 없음).
   - 선택이 없고 줌 ≥ 7 이며 화면 중심이 고정 관심 지역(한반도 원) 밖이면 **핫 리전(hot)** 수요: 중심을 0.5° 격자로 맞추고 반경 = min(250, 화면 반대각선) NM 을 50 NM 단위로 올림. 같은 셀은 세션끼리 공유한다.
   - 임대는 60 s 뒤 만료되고 세션이 살아 있는 동안 10 s 마다 갱신된다. 창을 닫거나 연결이 끊기면 최대 60 s 안에 호출이 멈춘다. 한 세션의 연속 집중 추적은 30분 상한(비용 상한) — 넘으면 화면이 알리고 다시 선택하면 이어진다.
2. **수집기는 임대만 읽어 조회한다.** focus: 활성 hex 전부를 5 s 마다 adsb.fi 묶음 요청 1회(최대 50 hex/요청). hot: 활성 셀마다 30 s 간격 `/v3/lat/lon/dist`.
3. **호출 상한은 수집기 한 곳에서.** 호스트별 토큰 버킷(adsb.fi 0.8 req/s, 공식 1 req/s 의 80 %)과 수집기 전체 상한, 하루 예산. 여유가 없으면 우선순위(고정 관심 지역 > focus > hot)대로 쓰고, hot 은 주기를 늘리고(30→60→120 s) 셀 수를 줄인다(세션 수 순). 상태(active·throttled·not_found)는 화면에 그대로 보인다 — 약속한 주기를 못 지키면 그렇다고 표시한다.
4. **병합은 신선도 우선.** 같은 hex 가 여러 출처(고정 지역·hot·focus·전세계)에 있으면 seen_at 이 가장 최근인 관측을 쓴다(출처 고정 우선순위는 오래된 값을 이기게 만들 수 있다).
5. **촘촘한 항적은 저장 경로 그대로.** focus 관측(5 s)은 기존 항적 저장(`track_point`, PK (hex, ts))으로 들어가 선택한 순간부터 5 s 간격 선이 된다.

## 대안과 기각 이유
- 브라우저가 공급자에 직접 요청: 키·약관·CORS·호출 상한을 통제할 수 없다(ADR-006 위반).
- hex 마다 개별 요청: 대상 수에 비례해 호출이 늘어 1 req/s 를 바로 넘는다. 묶음 요청은 대상 수와 무관하게 0.2 req/s.
- 핫 리전을 OpenSky bbox 로: 크레딧을 소모해 전세계 수집(ADR-009)과 충돌.

## 결과
호출량 상한(정상 사용 시 adsb.fi ≤ 0.5 req/s)과 사람이 보는 곳의 해상도(30 s / 5 s)를 맞바꾼다. 수요 임대·상태가 Redis 에 드러나 운영 화면에서 추적할 수 있다.
